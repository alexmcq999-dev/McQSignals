# McQ Signals: Telegram-бот с интрадей-сигналами по крипте

Бот каждые 15 минут сканирует самые ликвидные монеты с капитализацией от **$100M**, ищет сетапы на **15m** с фильтром тренда **1H** и присылает в Telegram готовый план сделки: вход, стоп, TP1 и TP2. Дальше он сопровождает каждый сигнал: пишет, когда взят TP1 (стоп в безубыток), TP2 или стоп, и ведёт статистику.

Всё работает бесплатно на **GitHub Actions**, сервер не нужен.

---

## Как бот принимает решение

Ни одна стратегия не работает всегда. Поэтому бот не полагается на один индикатор, а собирает **консенсус 11 классических стратегий** и учитывает режим рынка.

| Семейство | Модули | Когда работает |
|---|---|---|
| Тренд | EMA 20/50/200 (выстроенность), Supertrend (10,3), откат к EMA50 по тренду | в тренде |
| Импульс | MACD (кросс + гистограмма), RSI-режимы Cardwell, StochRSI-разворот по тренду | в тренде и в переходном режиме |
| Пробой | Дончиан 20 с объёмом (Turtle), Squeeze BB/Keltner (TTM) | на выходе из сжатия |
| Возврат к среднему | Возврат в полосы Боллинджера из перепроданности, дивергенция RSI | во флэте |
| Объём | VWAP (дневной) + OBV | всегда |

**Конвейер:**
1. **Вселенная монет.** CoinGecko даёт капу ≥ $100M. Стейблы, врапнутые и LST-токены отсекаются. Остаются монеты с оборотом на бирже ≥ $15M за 24ч, из них берутся 60 самых ликвидных.
2. **Режим рынка по ADX:** тренд (≥23), флэт (<18) или переходный. От режима зависит вес каждого семейства: во флэте трендовые голоса весят меньше, возврат к среднему больше.
3. **Сила сигнала 0–100.** Это взвешенная сумма голосов плюс бонусы за совпадение с трендом 1H, BTC и за всплеск объёма. Если сигнал идёт против тренда BTC, начисляется штраф.
4. **Фильтры:** сила ≥ 66, «за» голосуют минимум 5 модулей, сигнал не против тренда 1H, волатильность в норме.
5. **Триггер.** Сигнал срабатывает, только когда сила пересекла порог на этой свече. Если тренд просто продолжается, повторов не будет. По одной монете действует кулдаун 4 часа.
6. **Уровни.** Стоп ставится за свинг-экстремум последних 10 свечей, но в пределах 1–2.5 ATR и не дальше 4%. TP1 = 1.5R, на нём закрывается 50% и стоп переносится в безубыток. TP2 = 3R. Через 24 часа сигнал закрывается по времени.
7. **Размер позиции.** В сообщении есть подсказка, какой объём даёт риск 1% депозита.

## Запуск (10 минут)

### 1. Залить код в репозиторий

Распакуй архив и выполни в Терминале на Mac:

```bash
cd ~/Downloads/McQSignals        # папка, куда распаковал
git init -b main
git add .
git commit -m "McQ Signals bot"
git remote add origin https://github.com/alexmcq999-dev/McQSignals.git
git push -u origin main          # если репо не пустое: git pull origin main --allow-unrelated-histories, потом push
```

> Папка `.github` на Mac скрыта. Если заливаешь через сайт GitHub перетаскиванием, она не загрузится. Поэтому лучше через Терминал.

### 2. Секреты

GitHub → репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Секрет | Значение | Обязателен |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather | да |
| `TELEGRAM_CHAT_ID` | твой chat id (несколько можно через запятую, для канала указывай `-100…`) | желательно |
| `COINGECKO_API_KEY` | бесплатный Demo-ключ с coingecko.com/api (без него иногда бывает лимит) | нет |

**Никогда не коммить токен в код.** Если токен где-то засветился, выпусти новый в @BotFather командой `/revoke`.

### 3. Включить Actions

1. **Settings → Actions → General → Workflow permissions → Read and write permissions → Save.** Без этого бот не сможет сохранять состояние.
2. Вкладка **Actions** → *Scan signals* → **Run workflow**. Это первый ручной прогон.
3. Там же запусти *Backtest* → **Run workflow**. Через 3–5 минут отчёт появится в Summary, в папке `reports/` и в Telegram.
4. Напиши боту `/start`. На команды бот отвечает при следующем запуске, это до ~15 минут.

### 4. Минуты Actions

- **Публичный репозиторий:** минуты бесплатные и без лимита. Секреты при этом остаются скрытыми, видны только код и история сигналов.
- **Приватный:** лимит 2000 минут в месяц, а скан каждые 15 минут расходует около 2900. Поменяй cron в `.github/workflows/scan.yml` на `"1,31 * * * *"` (раз в 30 минут) или сделай репозиторий публичным.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | подписаться на сигналы |
| `/stats` | результаты за 7 дней, 30 дней и всё время: winrate, R, PF, просадка |
| `/open` | открытые сигналы |
| `/coins` | какие монеты сканируются |
| `/stop` | отписаться |

Каждый день в 09:00 МСК приходит отчёт за 24 часа. По воскресеньям бот сам запускает бэктест.

Чтобы бот стал приватным, поставь `telegram.allow_public_subscribe: false` в `config.yaml`. Тогда сигналы будут идти только в `TELEGRAM_CHAT_ID`.

## Версия v3: 1H + 4H, трейлинг, против толпы

**Почему v3.** Эксперименты v1/v2 на 120 днях показали, что на 15m ни один вариант не был в плюсе на честном (невиденном) периоде: комиссии съедали 0.2–0.5R на сделку. Поэтому:

1. **Таймфрейм 1H, фильтр тренда 4H.** Стопы в 3–4 раза шире, доля комиссий в риске падает. Открытые сигналы сопровождаются по 15m-свечам, так уведомления приходят быстрее.
2. **Трейлинг вместо TP2.** На TP1 = 1.5R закрывается 50% и стоп переносится в б/у. Остаток ведётся стопом «лучшая цена − 3 ATR», без потолка прибыли. Максимум 7 дней в сделке.
3. **Против толпы и манипуляций** (раздел `contrarian`):
   - **снятие стопов (liquidity sweep):** цена прокалывает 20-барный экстремум, где стоят стопы толпы, и закрывается обратно с длинной тенью на объёме. Это обязательный триггер контртрендового сигнала;
   - **перекос толпы на фьючерсах Binance:** соотношение лонгов и шортов по числу счетов (розница) против топ-трейдеров (крупные игроки). Если розница сильно перегружена в одну сторону, бот ищет вход в другую;
   - **Fear & Greed:** покупать страх, продавать жадность;
   - **фильтр толпы для трендовых сигналов:** не входить туда, где толпа уже перегружена.
4. **Новостной фон** из бота marketnews999. Бот не даёт новые сигналы за 45 минут до и после важных макро-событий (High impact), когда рынок дёргают и выносят стопы. В сообщении показываются тональность крипто-новостей, F&G и ближайшее событие. Новости на истории не проверить, поэтому это только риск-фильтр.
5. **Пометка «🧪 ТЕСТ»** (`telegram.test_mode`) стоит, пока стратегия не прошла проверку.

**Итог проверки v3 (360 дней, 25 монет, 3 периода):**
- контртрендовая ветка («снятие стопов» + перекос толпы) проиграла: −0.09R на сделку, в минусе 2 из 3 периодов. В v3.1 она **выключена**;
- тренд 1H/4H + **фильтр толпы** — лучший вариант: +0.08R на сделку, PF 1.13, просадка 23R. Фильтр толпы улучшил результат во **всех трёх** периодах. Первый период всё ещё в минусе, поэтому пометка «ТЕСТ» остаётся;
- следующая проверка — на 60 монетах: монеты с 26-й по 60-ю в настройке не участвовали, это честная проверка на новых данных.

**Проверка:** Actions → Backtest → `mode = experiments`. Бот прогонит 12 вариантов на 360 днях, разбитых на 3 периода по 120 дней. Рабочим считается только вариант с ✅, то есть в плюсе во всех трёх. По воскресеньям проверка запускается автоматически.

Данные толпы: `data.binance.vision` (дневные файлы metrics публикуются на следующий день, так что в бэктесте и в бою используется одинаковая задержка) и `api.alternative.me` (F&G).

## Настройка качества: как работать с бэктестом

1. **Actions → Backtest → Run workflow**, `mode = grid`. Бот переберёт пороги `min_score` × `min_agree` и сохранит таблицу в `reports/grid_latest.md`.
2. Не выбирай максимум прибыли. Это почти всегда подгонка под историю. Ищи **устойчивую зону**: PF > 1.2 после комиссий и **обе половины периода в плюсе**.
3. Впиши выбранные пороги в `config.yaml` и сделай push.
4. В отчёте `reports/backtest_latest.md` смотри раздел **«Вклад модулей»**. Модуль, который стабильно даёт отрицательный R, можно убрать из `signals.modules`.

Бэктест гоняет **ту же самую логику**, что и боевой сканер. Индикаторы каузальные, 1H берётся только по закрытым свечам, комиссия и проскальзывание вычитаются, а если стоп и тейк задеты в одной свече, засчитывается стоп. Тест `test_no_lookahead` проверяет, что сигналы не заглядывают в будущее.

```bash

```

## Источники данных

GitHub Actions работает на серверах в США, а `api.binance.com` оттуда закрыт (HTTP 451). Поэтому свечи берутся с официального зеркала **data-api.binance.vision**, где гео-блока нет. Если оно недоступно, бот сам переключается на **KuCoin**, затем на **OKX**. Выбрать источник принудительно можно переменной `DATA_PROVIDER` = `binance` / `kucoin` / `okx` (Settings → Variables).

## Ограничения

- Cron в GitHub Actions может запаздывать на 5–20 минут в часы нагрузки. Бот проверяет 3 последние закрытые свечи и не шлёт сигнал, если цена уже ушла больше чем на 0.5R от входа.
- Если в репозитории 60 дней нет активности, GitHub отключает расписание. Коммиты состояния от бота обычно считаются активностью, но раз в пару месяцев проверяй вкладку Actions.
- **Это не финансовый совет.** Ни одна стратегия не выигрывает всегда. Всегда ставь стоп и не рискуй больше 1–2% депозита на сделку.

## Структура

```
scan.py              боевой сканер (запуск раз в 15 мин)
backtest.py          бэктест и перебор порогов
config.yaml          все настройки
src/indicators.py    EMA, RSI, MACD, ATR, ADX, BB, Keltner, Supertrend, Donchian, VWAP, OBV, StochRSI, пивоты
src/strategies.py    11 модулей-стратегий
src/engine.py        режим рынка, скоринг, уровни, сопровождение сделки
src/data.py          капитализация и свечи (Binance vision / KuCoin / OKX)
src/telegram.py      отправка и форматирование сообщений
state/               состояние: открытые сигналы, история, подписчики
reports/             отчёты бэктеста
```
